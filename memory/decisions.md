# 决策记录

## ADR-001 镜头文件改用 GES 标准固定区间编码
日期：2026-09-28
背景：生成的 GES 工程文件（.esp）导入后镜头方向反向/错乱（用户实测 02 完全反向）。排查发现旧版按"自定义最小/最大值"归一化数值，而 GES 实际按固定标准区间解读（经度 ±180、水平转向 0~360 等）。
备选方案：（a）继续沿用旧仓库（mkatzef/google-studio-utils）的自定义区间编码；（b）按 GES 原生导出文件实测出的固定区间标准重写。
最终选择：（b）
原因：三方交叉验证一致——GES 原生导出样例、跑通 NeRF 训练管线的开源项目（jayin92/GES-utils）、Google Maps 相机官方定义；（a）已被用户实测证伪。
影响：全部 11 个 .esp 重写；此后镜头参数唯一来源 = make_video_assets.py 的 CLIPS 表，永不手改 .esp。

## ADR-002 文档采用"复制对"，不用符号链接
日期：2026-09-28
背景：要让不同 AI 工具（Claude Code / OpenCode / Codex）读到同一份项目文档（CLAUDE.md 与 AGENTS.md 两个文件名）。
备选方案：（a）符号链接；（b）两份物理文件逐字一致。
最终选择：（b）
原因：本机（Windows）建文件符号链接需管理员权限（实测失败）；坚果云只同步物理文件；生态内已有先例（internal-audit 项目同款）。
影响：每个有文档的目录 = CLAUDE.md + AGENTS.md 两份相同文件；改一份后必须立即 `Copy-Item` 覆盖另一份（命令写在文档开头）。

## ADR-003 .kml 重剪能力并入项目脚本（规则不再依赖临时区）
日期：2026-09-29
背景：11 份 .kml（路线图层）原由首版临时工具一次性生成，其剪取规则（含开场集结线特例、11_终章=母版整份）只存在于项目外的系统临时区，一旦被误清理即永久丢失；用户要求先并进项目。
备选方案：（a）把旧临时脚本原样复制进项目存档；（b）把剪取规则以 `generate-kml` 子命令并入 make_video_assets.py，并用"重剪结果与既有 11 份 .kml 逐字节一致"做验收。
最终选择：（b）
原因：（a）会把含已废弃 v1 编码（镜头反向的坑）的脚本留在项目里，误导后续接手者；（b）规则变成可执行、可回归验证的项目资产，且直接服务后续"新路线 → 新场景"。
影响：.kml 从"脚本不生成"调整为"可随时从母版重剪"；剪取规则从此只认项目脚本；既有 11 份 .kml 保持原样未被触碰。

## ADR-004 受众定位知识区观众（军迷视角仅作严谨标尺）
日期：2026-09-29
背景：需确定受众以推导详略、语速、时长与平台；此前以军迷视角拷问样片，但军迷并非目标。
备选方案：（a）军迷；（b）书粉；（c）知识区观众；（d）学生/教学。
最终选择：（c）
原因：军迷视角的价值在于"借严谨"（事实层无硬伤），而非决定呈现形态；2.5 分钟动画短片天然适配知识区传播；书粉与学生可为后续延展，不做首要目标。
影响：路线加密以"无硬伤＋关键锚点"为度，不做军迷级穷尽；Q17 核心论点前置为钩子与标题；考证分歧转为简介区"考证说明"资产；平台按知识区规格走（封面、全字幕必备；竖屏版与配音人选待定）。

## ADR-005 项目定位重定义：从"做一部片"升级为"造一套 AI 视频系统"
日期：2026-10-13
背景：14 天技术攻坚（GES 编码修复、ABC 探针、03 高版、沙盘引擎试点）后用户判定：工具路线都试过了，"真实地形照片"语法始终给不出想要的成片感。用户从头重述目的：①本项目只是测试用例，真产品是"一套用 AI 造视频的系统（skill/hooks/workflow harness）"；②成品类型=军事地理地理解读纪录片，**主角是地形**（山河湖的难度与必要性），战争只是叙事引子；③半成品外交给剪辑软件拼尾。
备选方案：（a）继续在现有管线修画面参数；（b）承认形态未定，回到"目的→形态→工具"的顺序重建。
最终选择：（b）
原因：两周教训——我一直在修"怎么画"，从没拉齐过"画成什么样算对"；技术选型在形态未定时是伪选择题。
影响：
- 成片规格锁定：**竖屏 9:16（1080×1920）；时长不锁死，由内容的事实密度定**（分镜层拿定义权）
- 竖屏构图语法新立：翻山=剖面仰视语法；路线地图"卡片化"；**横屏裁竖屏已被证伪**（10-12 晚 E 探针），每镜头必须竖屏原生
- 分工裁决写死："几何正确归机器，观感受众归剪辑"——判别口诀：改动的活要不要写代码
- 渲染器易主 [推测待验证]：竖屏地形片主渲染器=自建引擎（画布自由+剖面语法），GES 降为"横屏空镜备用库"；GES 功夫沉淀为"镜头配方表+verify 校验"的中间件思想
- 系统抽象脊柱：①事实层→②叙事层→③素材层（配方表→渲染器插件）→④出厂（后期包清单）→⑤复盘写回 skill

## ADR-006 后期自动剪辑选型：baocut（JimLiu/baocut）为流水线最后一棒
日期：2026-10-13
背景：用户指定评估 JimLiu/baocut 能否承担"AI 自动剪辑"角色（此前只有剪映人工一条路）。
备选方案：（a）继续纯剪映人工；（b）接入 baocut 作自动剪辑手；（c）自研 ffmpeg 拼装器。
核查（librarian 侦察，2026-10-13，HEAD=745a5ca）：本地桌面应用+"AI 可指挥"剪辑台，CLI/MCP 双入口操作同一条时间线，也可手改；需求六项全过（导入素材/JSON 操作拼装带 --dryRun/字幕文字/竖屏1080×1920/导出mp4/活跃：856 star 建库 2026-07 次日仍在提交）；关键缺口=无"读清单→一键成片"现成功能，需自写"后期包清单→edits_apply 操作序列"翻译器；坑=许可证 BaoCut Community License 1.0（内容免费商用，卖软件/托管要商业授权）+重（ffmpeg+本地模型）+新项目接口变动风险+纯机械 export 无头运行未实测[推测]。
最终选择：（b）；剪映保留为人工微调备份；（c）留作被卡死时的备胎——翻译器若受阻，ffmpeg 直拼是最简降级路径。
原因：六项全中且"AI 可指挥"直接补上流水线最薄的后期层；接入成本一个转换器不至于重写管线。
影响：待用户批准安装+写翻译器；试点=11 终章现成素材+后期包照单自动拼竖屏版。
