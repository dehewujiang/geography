# 经验教训

## 教训-001：GES 工程文件数值必须按固定标准区间编码（2026-09-28）
- 案例：v1 生成的 11 个 .esp 导入后镜头方向反向/错乱（用户实测 02 完全反向）
- 根因：沿用 2022 年旧仓库的自定义 min/max 归一化（且缺 maxValueRange、方位角为负），与 GES 实际读取方式不符
- 固化：标准编码表见 make_video_assets.py 头部 [PROTOCOL] 与 context.md；**不要重新调研**，不要再引旧仓库编码
- 同类工作提前注意：生成/修改 .esp 前先对照编码规范；改完必跑 `verify`

## 教训-002：Windows 符号链接需管理员权限 → 文档用复制对（2026-09-28）
- 实测 `New-Item -ItemType SymbolicLink` 失败（需管理员/开发者模式）
- 采用方案：CLAUDE.md + AGENTS.md 两份物理文件逐字一致，改一份立即 `Copy-Item` 覆盖另一份
- 适用范围：本机所有坚果云项目（生态惯例，internal-audit 项目同款）

## 教训-003：收工/开工协议靠主动加载，不是自动注入（2026-09-28）
- 案例：用户说"收工"后未执行结束协议、未生成记忆文档，被用户指出后才补
- 根因：memory_rules.md 设计为"按需主动读取"（不自动注入；hooks 里也没有相关自动钩子），而我当时只做了口头总结
- 固化：会话开始 → 读记忆三件套（session/TODO/project，缺失则初始化）；听到"收工/结束/今天到这里" → 先读 rules/memory_rules.md 再执行结束协议
