# 抽屉：设计环（design loop — 分镜的 previz 工序）

> 一句话：分镜也走先红后绿——LLM 设计稿（配方表格式）先过机器卡口（红→绿），再出关键帧预演板让用户做选择题，锁版才准渲染；设计理由与复盘落盘，模板库长经验。
> 地位：流水线第 2.5 步（叙事定稿 ⟶ **设计环** ⟶ 呈现生成）。行业标准词=previz / storyboard（见 `lexicon.md`）。

## 输入（七样齐才开工）

1. 事实卡（本集，fact-auditor 三查过；**含编号条目层**，见 `step1-fact.md` §6.1）
2. **地理摘要（2026-10-13 新增：代码产，LLM 收货）**——脚本从母版路线+高程数据自动算一页"地形要点表"：每段距离/最高点海拔/最陡段/急弯处/跨河次数+关键段地形特征。**LLM 看不见地形，drama 在地图不在文案**；没有这一页不许进设计。
3. 文案定稿+节拍（step2）
4. 风格规格（根目录 `memory/decisions.md` ADR-007：二抄一反）
5. 模板库+能力表（`shot-templates.md`；词汇=lexicon 全部镜头原子）
6. 上集复盘+问题单+系列连续性约定
7. **本主题粮库清单+效果-数据映射表**（2026-10-13 追加：导演的"食材能力册"，见 `data-sources.md` 三层制；导演点菜、备菜脚本下厨）

## 备菜工序（前置闸门，2026-10-13 新增）

事实锁死后、设计环开工前：脚本按 bbox+事实需求算缺料 → 下载入 `粮库/` → 写 manifest → 生成粮库清单页。**manifest 不齐，设计环不开工**（渲染同理）。

## 三步

### 第0步 地理摘要（新增前置：**机器先于 LLM 动手**）
- 脚本从母版路线+高程数据算"地形要点表"（每段：距离/最高点海拔/最陡段/急弯/跨河），存随集事实页。
- 这道工序是**代码的活**，记引擎待办；LLM 收到的必须是算好的表，不是原始地形让它猜。

### 第1步 LLM 分镜草案
**角色任命（2026-10-13 追加）**：导演×摄影指导双帽——导演管"观众此刻必须知道什么"，摄影指导管"用什么镜头让他知道"。作业总纲（编排之尺）：**每一拍必须比上一拍让观众多知道一件确定的事**（信息增量单调：禁复制、禁跳跃）。每拍须过"删掉这拍观众少了什么"质询，答不出直接砍（治 LLM 爱加戏）。迭代 ≤3 轮封顶。
**镜头语法决策矩阵（俯/仰/拉高不是感觉，是岗位表）**：

| 拍的岗位 | 镜头语法 | 判定口诀 |
|---|---|---|
| 定位 | 俯视广域+north-up | 主角=点/线→俯 |
| 领路 | 平视跟随+中高度 | 主角=坎/山→仰 |
| 震撼 | 仰视+高程夸张+近地 | 主角=关系/范围→拉高 |
| 解读 | 剖面/对比/数字卡 | 文案动词自带提示("经过"→领路)，但数字底线硬压美学 |
| 收束 | 拉升摇臂 | |

- 强制输出格式：镜头配方表条目 + 后期包条目/形状起草（`post-production.md` 定义），**每行三证栏：引用事实编号（F-##）+ 用哪一层数据（粮库名）+ 选择理由**——理由必须绑定事实或观众常识，禁止"感觉"。点菜只能点手册里的；表上没有的效果标"需开发+需要什么数据"，不许装作能拍。
### 第2步 机器卡口（第一道 hook，不看内容只查合法性）
- 镜头类型在能力表内？（不在→打回）
- 高度/俯仰/离地符合晕动底线？（离地 minimum ground clearance 数字复用 cinematography）
- 每拍时长/节拍/文案字数在规格内？
- 路线生长单调递增、朝向步进无突变（跳变只允许出现在字卡切点）？
- 任一不过→原地打回 LLM 重写，不进第3步。
### 第3步 关键帧预演板
- 配方表直接算 6~9 张静帧（路线+标注+构图，不进 3D 渲染，秒级）；加每拍一句话功能注释，拼一页。
- 里程碑帧必须含：开场全景正北终结帧、定位标签帧、路线中段帧、翻山A/B双帧、收束帧。

## 用户拍板规则（前置约束，防烂尾）

- **只递选择题**：每处争议给 2~3 个候选+各自代价，禁开放题（"觉得整体如何"之类不许问）。
- 只看预演板，不做参数细节讨论。
- 拍板=锁版签名；**没锁版不渲染，锁版后修改=回设计环重走**（单向不回流的分镜版）。

## 锁版之后

渲染 → 看片 → 问题单 → 复盘写回：本集"哪拍被赞/哪拍被槽"化作模板库修改建议（如 T-01 加天时档）。设计环的"好坏"由这条回路由弱变强。
