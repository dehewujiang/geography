# 分卡D：AI读书提炼出母版（本书用的就是这条路）

> 什么时候用：有书稿没坐标、地点散在文字里时。本书母版就是这么来的：AI读epub、按意图提地点、跑脚本生成，再和书比对。[文件确认]

## 三段走（顺序不能乱）

1. **读书**：把书稿（epub/txt）给AI，说明意图，如“只提1253-1259行军路线上的分兵点和战场，不过村庄”。
2. **提炼成表**：AI输出地点表（地名/上下文页码/疑似经纬度/存疑标记），人先过一遍，删掉编的、标出存疑的——这步不许跳，AI地名一定有错的。
3. **跑脚本生成**：地点表定稿后才生成kml（本项目用的是临时脚本+xml解析 + 开源 `mkatzef/google-studio-utils` 只管esp格式，不管坐标真假；坐标真假只由第2步的人审定）。

## 铁律

- 开源库只管格式对不对，不管地点真不真——真假只认书和第2步的人审。
- 生成脚本当时在系统临时区，没进项目（这就是后来ADR-003只找回剪取规则的原因）；新书跑这条路时，脚本必须存进项目，下次直接复用。[文件确认]
- 产出和其他三法一样：根目录一个母版kml + `素材/`一行来源说明（含书名+版本+提炼日期）。

## 检查

- 地点数对得上书：多一个少一个都要问。
- Google Earth打开走一遍：线顺、名字是书中叫法、无“未命名”。
