# 事实审校模块（历史/地理事实防错）

> 定位：第 1 步（事实锁死）的守门人。AI 生成的历史叙述一切以独立来源复核为准，禁止自证。
> 触发：新主题建事实卡时、母版 KML 写 description 时、解说文案定稿前。

## 1. 底稿纪律

- 一切事实的唯一底稿 = 该主题的**母版 KML**（地名坐标 + 描述）；事实卡从底稿派生，不改底稿就改文案 = 违规单。
- 母版 KML 的 `description` 第一句必须声明精度性质（本项目模板："坐标为现代地名大致对应，仅用于讲故事摆镜头，非考古精确位置"）。
- 母版地标数是脚本的硬断言（本项目 17 处）——增删地标必须同步改脚本断言，跑 `verify`。

## 2. 审校规则（三查）

| 查什么 | 怎么查 | 不过怎么办 |
|---|---|---|
| 查冲突：同一事件不同文料的年代/路线/地名说法 | 至少两个独立来源对照（不是同一来源转引） | 冲突写进事实卡"存疑区"，选主流说法，备注矛盾 |
| 查地点：现代地名 ↔ 历史地名对应是否可靠 | 权威断代史/期刊，或地图工具反查 | 对应不稳的 → 母版坐标改标"大致"，文案改模糊表述 |
| 查"看起来对"：具体数字（兵力/里程/年份）最易错 | 逐个数字回溯出处 | 查不到 → 文案删数字，不猜 |

## 3. 标注义务（贯穿全程）

- 全企划共用六标签：[运行确认][文件确认][文档确认][用户确认][推测][无据]——事实卡与解说里一切结论贴标。
- [推测] 混进事实卡=silent failure：读者永远不会知道那是猜的。宁可空着，不可编造。
- 解说词里允许"戏剧化但不可虚构"：允许渲染情绪，禁止虚构事件。

## 4. 红线

- 涉及现代地缘/民族叙事（本项目安南=越南等段落）：只按史料事实陈述，价值判断交给用户。
- 用户说"就这么写"以用户为准，但先出示风险再执行（写进问题单，不写进事实卡）。
